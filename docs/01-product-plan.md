## 1. 方案结论

当前项目已经具备可演示 MVP：支持图片上传、本地 Transformers.js 识别、Gemini 结构化摄影分析、术语气泡、结果展示和 JSON 下载。建议将产品定位从“通用照片识别工具”收敛为“面向摄影学习者和内容创作者的照片质量诊断与优化建议 Agent”。

下一阶段明确不做自动改图和生成式修图，产品重心放在“看懂当前照片情况、指出存在问题、给出可执行改进建议”。基础能力默认由小模型、IQA 工具、传统 CV 指标、EXIF 和规则引擎完成；Gemini、OpenAI、Qwen 等大模型只作为可选高级配置，用于深度点评、叙事分析和建议润色。后续即使出现裁剪框或后期参数，也只作为建议和可视化标注，不自动生成修改后的图片。

## 2. 背景与问题

摄影学习者、内容创作者和普通用户常见问题不是“看不懂照片里有什么”，而是“不知道照片现在处于什么水平、具体问题在哪里、下一次怎么拍、本次后期怎么改”。现有项目已经把照片识别结果转成构图、光影、色彩和技巧建议，但仍存在三类产品问题：

- 结果可信度不够透明：本地模型偏通用分类，Gemini 依赖用户自行填写 Key。
- 分析维度仍偏少：当前主要围绕构图、光影、色彩，尚未系统覆盖主体、清晰度、景深、噪点、情绪叙事、场景意图、发布适配和后期空间。
- 改进建议还偏文字化：缺少问题证据、优先级、可执行动作、参数化建议和交互式复盘。
- 产品闭环偏一次性：没有历史记录、项目管理、批量横评和学习路径。

## 3. 产品合理性反思

成立的部分：

- 纯前端 MVP 降低部署成本，适合个人工具、教学演示和快速验证。
- 小模型和工具链可以覆盖模糊、曝光、色彩、比例、主体/场景识别、基础美学分等大部分基础质量判断。
- Gemini 结构化 JSON 能提供比 ImageNet 分类更接近摄影分析的深度点评输出，适合作为高级增强模式。
- 术语气泡能把分析结果转成学习资料，适合摄影教学场景。

高风险部分：

- 如果基础分析过度依赖大模型，成本、稳定性、隐私和响应时间都会变成早期产品风险。
- 纯前端直连 Gemini 会暴露 API Key，不适合正式产品。
- 单一的本地 Transformers.js 模型只能识别主体和场景，必须补充 IQA、CV 指标和规则，才能形成可用的质量诊断。
- 如果过早做“自动改图”，会显著增加模型成本、失败率和用户预期管理难度，也会把产品焦点从“学习与判断”带偏到“生成结果好不好”。

修正后的判断：

MVP 应聚焦“上传照片 -> 小模型/工具基础分析 -> 当前情况 / 存在问题 / 如何改进 -> 导出 / 复盘”。V1 重点补齐“建议优先级、视觉标注、评分对比、后期参数建议”。大模型能力保留为可选高级分析配置，不作为基本流程的强依赖；自动改图和生成式修图暂不进入产品路线。

## 4. 目标与成功标准

业务目标：

- 将项目从功能演示整理为可持续迭代的摄影分析工具。
- 形成清晰的 MVP、V1、V2 范围，避免需求发散。

用户目标：

- 快速知道一张照片在构图、光影、色彩、清晰度、主体表达、叙事氛围、技术质量和发布适配上的主要问题。
- 获得下一次拍摄和本次后期可执行的优化建议。
- 能保存分析结果，用于复盘、教学或作品筛选。

成功指标：

| 指标类型 | 指标 | 目标值 | 统计口径 |
|---|---|---:|---|
| 用户体验 | 单张照片完成分析时间 | 基础模式 10s 内，高级模式 15s 内 | 从点击分析到结果渲染 |
| 内容质量 | 建议可执行率 | 80% 以上 | 人工抽样判断是否能直接操作 |
| 分析覆盖 | 核心维度覆盖率 | 8 个以上 | 单张结果中覆盖的有效分析维度 |
| 交互效率 | 用户定位首要问题时间 | 30s 内 | 从结果出现到用户找到最高优先级问题 |
| 稳定性 | 分析失败可恢复 | 100% | 失败时有错误原因和回退结果 |
| 安全 | API Key 暴露风险 | V1 必须移除 | 大模型高级模式由后端或 Serverless 代理调用 |

非目标：

- 不在 MVP 阶段做账号系统、社区、作品交易、图库托管。
- 不在当前阶段做自动改图、生成式修图、图片替换或“一键变好看”。
- 不把单一小模型或单一美学分包装成专业摄影评分结论。

## 5. 目标用户与核心场景

| 用户类型 | 核心诉求 | 高频场景 | 当前痛点 | 产品价值 | 优先级 |
|---|---|---|---|---|---|
| 摄影学习者 | 知道照片问题和改法 | 拍完照片后复盘 | 不知道问题在构图还是光线 | 获得教学式诊断 | P0 |
| 内容创作者 | 快速筛选可发布照片 | 多张照片批量挑选 | 人工筛片慢，标准不稳定 | 评分和建议辅助筛选 | P1 |
| 摄影老师/社群运营 | 给学员批改作品 | 作业点评、课程反馈 | 点评重复、耗时 | 自动生成初稿 | P1 |
| 普通用户 | 让照片更好看 | 旅行、人像、探店 | 不懂摄影术语 | 给简单建议 | P2 |

核心用户故事：

1. 作为摄影学习者，我希望上传一张照片后看到多维评分、首要问题和改进动作，从而知道优先改哪里。
2. 作为内容创作者，我希望批量上传照片并按评分排序，从而快速挑选可发布作品。
3. 作为老师，我希望导出每张照片的结构化 JSON 或报告，从而复用为点评材料。

## 6. 产品定位与边界

产品定位：

面向摄影学习与内容创作的照片质量诊断 Agent，提供多维结构化评分、专业术语解释、问题定位和可执行优化建议。

核心差异：

- 不只识别“图里有什么”，而是输出“照片哪里好、哪里弱、怎么改”。
- 不只给自然语言评价，而是保留结构化 JSON，方便后续做报告、排序和批量处理。
- 默认支持小模型、IQA、CV/EXIF 和规则引擎组成的基础分析；大模型作为可选增强，兼顾隐私、成本和质量上限。

做什么：

- 图片上传、队列、删除、预览。
- 模型配置，默认基础分析模式和可选大模型高级分析模式切换。
- 多维质量分析：构图、光线、色彩、清晰度、主体、景深、噪点、情绪叙事、技术质量、发布适配。
- 当前情况、存在问题、如何改进三段式建议。
- 拍摄侧建议、后期侧建议、发布侧建议和学习侧建议。
- 术语解释和资料链接。
- 单张结果 JSON 下载。

不做什么：

- 不做用户账号和云端相册。
- 不做完整图片编辑器。
- 不做自动改图、生成式修图和图片替换。
- 不做真实专业评分模型训练。
- 不做自动商业版权判断。

## 7. 业务流程

主流程：

```text
进入页面 -> 上传照片 -> 选择基础分析或高级分析 -> 点击开始分析 -> 查看当前情况 -> 定位高优先级问题 -> 查看拍摄 / 后期 / 发布建议 -> 下载 JSON / 复盘建议
```

分支流程：

- 文件格式不支持：提示跳过文件名。
- 未配置大模型 Key：提示继续使用基础分析，或配置高级分析 Key。
- 模型加载失败：保留回退结果，展示失败原因。
- 用户删除照片：同步删除对应分析结果并释放预览 URL。

关键状态：

| 对象 | 状态 | 触发事件 | 下一状态 | 说明 |
|---|---|---|---|---|
| 照片 | 待分析 | 上传成功 | 分析中 | 进入队列 |
| 分析任务 | 分析中 | 点击开始分析 | 成功 / 回退 | 当前为前端串行处理 |
| 结果 | 成功 | 分析引擎返回 | 可查看 / 可下载 | 含小模型 / 工具指标 / 可选大模型结果 |
| 结果 | 回退 | 模型异常 | 可查看 / 需提示 | 使用规则生成兜底结果 |

## 9. 功能范围

### 9.0 多维分析体系

单张照片的结果应按“当前情况、存在问题、如何改进”组织，同时覆盖以下维度：

| 分析维度 | 当前情况 | 存在问题 | 如何改进 |
|---|---|---|---|
| 构图与画面组织 | 主体位置、重心、边缘、留白、比例 | 主体偏移、边缘干扰、画面失衡、无效空间 | 机位移动、裁切建议、横竖构图建议、主体位置调整 |
| 光线与曝光 | 光源方向、明暗层次、动态范围 | 过曝、欠曝、光线平、阴影脏、高光丢失 | 曝光补偿、测光策略、拍摄时段、补光方向 |
| 色彩与白平衡 | 主色、冷暖、饱和度、肤色 | 色偏、饱和度过高、色彩混乱、主体不突出 | 色温调整、降低干扰色、统一色调、增强主体色 |
| 清晰度与技术质量 | 对焦、锐度、噪点、运动模糊 | 跑焦、手抖、噪点高、压缩痕迹 | 快门速度、ISO、对焦点、降噪和锐化建议 |
| 主体与层次 | 主体识别度、前中后景、背景分离 | 主体不明确、背景抢戏、层次扁平 | 改变距离、光圈、背景选择、主体隔离 |
| 景深与镜头语言 | 景深深浅、透视、焦段感 | 景深不服务主题、透视变形、压缩不足 | 光圈、焦段、拍摄距离和视角建议 |
| 情绪与叙事 | 瞬间、表情、氛围、故事线 | 情绪弱、信息分散、缺少观看理由 | 等待瞬间、强化环境线索、选择更明确主题 |
| 后期优化空间 | 可修复问题、局部调整空间 | 后期方向不清、处理优先级混乱 | 裁切、曝光、色彩、局部蒙版、质感调整 |
| 发布适配 | 社媒比例、封面可读性、缩略图识别 | 缩略图主体不清、比例不适配 | 输出比例建议、标题区留白、封面裁切建议 |

P0 必须做：

| 功能 | 用户价值 | 需求说明 | 验收标准 |
|---|---|---|---|
| 图片上传与队列 | 快速进入分析 | 支持 jpg、jpeg、png、webp，多图上传和删除 | 非图片提示跳过，删除后结果同步移除 |
| 基础分析引擎 | 不依赖大模型也能完成分析 | 使用小模型、CV 指标、EXIF、规则引擎生成基础诊断 | 不配置大模型 Key 也能输出当前情况、问题和建议 |
| 模型 / 工具配置 | 适配不同质量和成本 | 支持基础模式、ViT、CLIP、CV 指标开关和可选大模型配置 | 切换后参数联动正确 |
| 多维结构化分析 | 给出明确诊断 | 输出当前情况、存在问题、如何改进 | 至少覆盖构图、光线、色彩、清晰度、主体、叙事、后期、发布适配 |
| 问题优先级 | 帮用户知道先改什么 | 为问题标记高 / 中 / 低优先级 | 结果页能看到首要 3 个问题 |
| 建议分类 | 提升行动性 | 按拍摄、后期、发布、学习分组 | 每组至少给出 1 条可执行建议 |
| 可选高级分析 | 满足更高质量点评 | 用户配置大模型后，补充叙事、情绪、复杂构图和建议润色 | 基础结果不被高级分析阻塞 |
| 错误回退 | 保证可用性 | 模型失败时生成兜底结果 | 页面不崩溃，有失败原因 |
| JSON 下载 | 支持复盘和二次处理 | 单张结果导出 | 不包含 Gemini API Key |

P1 应该做：

| 功能 | 用户价值 | 需求说明 | 验收标准 |
|---|---|---|---|
| 后端 / Serverless 代理 | 避免 Key 暴露 | 大模型高级分析由服务端调用 | 前端不再出现用户 Key |
| 批量排序与对比 | 提升筛片效率 | 按综合分或维度分排序 | 多图时可快速定位最佳图 |
| 视觉标注建议 | 提升可执行性 | 在原图上标注边缘干扰、主体区域、建议裁切框 | 只做标注和建议，不自动改图 |
| 历史记录 | 形成学习闭环 | 本地或云端保存分析记录 | 可按日期和文件名查找 |

P2 后续做：

| 功能 | 用户价值 | 需求说明 | 触发条件 |
|---|---|---|---|
| 报告导出 | 教学和社群运营 | 导出 PDF / Markdown 报告 | 有老师或社群使用需求 |
| 评分标定 | 提升专业可信度 | 引入样例集和人工评分基准 | 有足够真实用户反馈 |
| 提示词 / 拍摄任务卡 | 形成学习路径 | 根据问题生成下一次拍摄练习任务 | 用户有连续复盘需求 |

## 10. 页面与交互要求

| 页面 / 模块 | 使用角色 | 核心任务 | 关键组件 | 优先级 |
|---|---|---|---|---|
| 首页工作台 | 全部用户 | 上传并分析照片 | 上传区、模型配置、分析按钮、结果区 | P0 |
| 模型配置面板 | 进阶用户 | 控制基础工具和高级模型 | 基础模式开关、preset、topK、候选标签、高级模型 Key 保存方式 | P0 |
| 分析结果卡片 | 全部用户 | 查看诊断和建议 | 图片预览、评分、当前情况、问题排序、改进建议、JSON | P0 |
| 多维诊断面板 | 全部用户 | 展开查看每个维度 | 维度 Tab、优先级、证据、建议动作 | P0 |
| 批量对比视图 | 内容创作者 | 筛片和横评 | 排序、筛选、对比表 | P1 |
| 视觉标注层 | 进阶用户 | 理解问题位置 | 主体框、干扰区域、建议裁切框、留白提示 | P1 |

核心交互：

- 结果顶部先给“结论摘要”：综合分、适合场景、首要问题、最值得做的一步。
- 每个维度采用三段式卡片：当前情况、存在问题、如何改进。
- 问题列表按优先级排序，并允许用户展开查看原因。
- 建议按“拍摄时怎么改、本次后期怎么修、发布前怎么处理、下一次怎么练习”分组。
- 原图区域保留未来标注能力：先展示图片，后续叠加主体、干扰物、留白和裁切建议。
- 结果支持复制建议、下载 JSON，后续支持导出点评报告。

体验原则：

- 保持工作台式界面，不做营销落地页。
- 所有失败都要可理解、可恢复。
- 术语解释不打断主流程。
- 不用“神奇修图”式话术，避免暗示系统会自动改图。
- 对 API Key、云端分析、数据上传给出明确提示。

| 数据对象 | 关键字段 | 创建方 | 使用方 | 生命周期 |

- MVP 无账号权限，所有数据默认停留在浏览器会话。
- 基础分析模式默认不把图片发往云端。
- 高级大模型模式会把图片发往第三方 API 或后端代理，应在正式产品中增加明确授权提示。
- API Key 不进入导出 JSON；V1 应迁移到后端代理。

## 12. 规则与策略

| 规则类型 | 规则说明 | 生效范围 | 例外情况 |
|---|---|---|---|
| 文件规则 | 仅接受 jpg、jpeg、png、webp | 上传模块 | 后续可补充 heic |
| 分析模式规则 | 基础分析为默认模式，高级大模型为可选模式 | 全产品 | 用户主动配置高级模型时启用 |
| 评分规则 | 小模型 / 工具指标 / 规则先生成基础分，大模型只补充解释和建议 | 分析结果 | 单一小模型不宣称专业评分 |
| 建议规则 | 每条建议必须说明适用场景和动作方向 | 分析结果 | 无法判断时标注“需人工复核” |
| 改图边界 | 只输出建议、标注和参数方向，不替换原图 | 全产品 | 后续版本另行评审 |
| Key 存储 | 默认 session，可选 localStorage | 高级大模型配置 | 正式产品迁移服务端 |
| 导出规则 | 下载单张结果 JSON，不包含 API Key | 结果卡片 | 后续可增加批量导出 |

## 13. 非功能需求

- 性能：基础分析应尽量轻量，首次本地模型下载需要可感知进度；后续分析应复用浏览器缓存。
- 安全：V1 必须移除纯前端 API Key 暴露风险。
- 可用性：无图、格式错误、Key 缺失、模型失败均需有明确提示。
- 可观测性：V1 增加前端错误日志、模型失败类型、耗时统计。
- 兼容性：优先支持 Chrome、Edge、Safari 最新版本；移动端作为 P1 优化。

## 14. 验收标准

MVP 验收：

1. `npm run build` 可以成功通过。
2. 上传合法图片后可展示队列和缩略图。
3. 不配置大模型 Key 时，基础模式可完成图片识别、质量指标分析和结构化建议。
4. 配置大模型 Key 后，高级模式可补充深度点评，但基础结果不被高级模式阻塞。
5. 分析结果至少包含当前情况、存在问题、如何改进三类内容。
6. 结果中明确区分拍摄建议、后期建议和发布建议。
7. 单张结果可下载 JSON，且不含 API Key。

当前验证：

- 2026-05-28 已运行 `npm run build`，构建通过。
- 构建提示主 JS chunk 超过 500 kB，属于 V1 性能优化项。

## 16. 技术可行性与成本结论

技术可行性：可行。前期不需要强依赖大模型，现有前端 MVP 可以演进为“小模型 + 工具 + 规则”的基础分析产品；正式产品若启用大模型高级分析，再通过后端或 Serverless 代理承接 Key、日志和额度控制。

复杂度评估：

- 低复杂度：文档整理、页面文案、错误提示、结果下载、术语库扩展、基础规则建议。
- 中复杂度：多维结果结构、问题优先级、小模型/工具指标编排、批量排序、历史记录、视觉标注。
- 高复杂度：Serverless 大模型代理、专业评分标定、建议质量评估、模型成本控制。

成本与周期建议：

- V0.1 稳定化：1 到 2 天。
- V0.5 可试用：1 到 2 周。
- V1.0 公开试用：3 到 4 周。

技术建议采纳：

| 技术建议 | 是否采纳 | 原因 |
|---|---|---|
| 基础分析默认使用小模型和工具 | 是 | 降低成本，保障无 Key 可用 |
| 大模型作为可选高级配置 | 是 | 提升点评深度，但不绑定基础流程 |
| 大模型 Key 迁移到服务端代理 | 是 | 解决正式产品安全风险 |
| 当前阶段不做自动改图 | 是 | 先验证诊断与建议价值，避免成本和预期失控 |
| 增加多维分析和问题优先级 | 是 | 符合用户“知道哪里不好、先改哪里”的核心诉求 |
| 增加批量对比和视觉标注建议 | 是 | 与筛片、复盘和教学场景强相关 |

## 17. 商业与运营策略

可选路径：

- 个人工具：免费使用基础分析，自带 Key 使用大模型高级分析。
- 教学工具：按班级或课程售卖批改报告能力。
- 内容创作者工具：免费分析 + 高级批量筛片 / 报告导出付费。

冷启动建议：

- 先找摄影学习者或小型摄影社群试用。
- 收集“当前情况是否准确”“问题是否说到点上”“建议是否能执行”“最想要的交互能力”。
- 用真实反馈修正评分和文案模板。
